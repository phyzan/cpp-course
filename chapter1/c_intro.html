3  Εισαγωγή στην C

Πριν ξεκινήσουμε να μελετούμε την ίδια την C++, καλό είναι να κατανοήσουμε πρώτα κάποια βασικά στοιχεία της C. H C είναι μία γλώσσα με σχετικά μικρή σύνταξη, ενώ ταυτόχρονα δίνει στον προγραμματιστή πολύ μεγάλες δυνατότητες, όπως τον έλεγχο του υπολογιστή σε πολύ χαμηλό επίπεδο και την λεπτομερή διαχείρηση μνήμης.

Στην πορεία των μαθημάτων, θα χρησιμοποιούνται διαδραστικά κομμάτια (blocks) από κώδικα, ο οποίος εκτελείται σε εξωτερικούς servers και δεν απαιτείται εγκατάσταση κάποιου προγράμματος, αν και για τις ασκήσεις η τοπική εγκατάσταση των compilers θα είναι απαραίτητη.

3.1 Ένα πρώτο πρόγραμμα

Τροποποιήστε τον παρακάτω κώδικα και πατήστε ▶ Εκτέλεση (ή Ctrl+Enter) για να τον μεταγλωττίσετε και να τον τρέξετε:

#include <cstdio> // Contains the `printf` function

int main() {
    printf("It's ALIIIIVEEE");
    return 0;
}

Παρατηρούμε διάφορα γλωσσικά στοιχεία ή λεκτικές ομάδες σε αυτό το μικρό κομμάτι κώδικα, όπως το #include ή το printf. Ο ρόλος κάθε στοιχείου θα μελετηθεί ξεχωριστά.

3.2 Τύποι αρχείων

Τα αρχεία που ο compiler διαβάζει για να συνθέσει ένα πρόγραμμα ανήκουν σε δύο κατηγορίες:

  1. Αρχεία κεφαλίδων (header files), με επέκταση .h (κυρίως για την C) ή .hpp (προτιμότερο για την C++, αλλά δεν έχει σημασία, είναι απλά σύμβαση), τα οποία περιέχουν δηλώσεις συναρτήσεων, σταθερών και άλλων στοιχείων που μπορούν να χρησιμοποιηθούν από άλλα αρχεία του προγράμματος. Είναι σημαντικό πως συνήθως περιέχουν την δήλωση των στοιχείων αυτών, και όχι την υλοποίησή τους (δεν είναι απαραίτητο αυτό, αλλά αργότερα θα δούμε πως αν δεν τηρούμε την σύμβαση μπορούν να δημιουργηθούν προβλήματα). Ουσιαστικά λένε στον compiler πως κάπου υπάρχουν αυτές οι μεταβλητές ή συναρτήσεις με αυτά τα ονάματα, αλλά την υλοποίησή τους θα την βρει αλλού, και απλά ο linker, μετά την μεταγλώττιση, θα πει στο τελικό πρόγραμμα πού να βρει τις διευθύνσεις μνήμης των στοιχείων αυτών όταν εκτελεστεί.

  2. Αρχεία πηγαίου κώδικα (source files), με επέκταση .c για την C, ενώ για την C++ συνηθίζεται η .cpp ή .cc. Περιέχουν την υλοποίηση των συναρτήσεων και της υπόλοιπης λειτουργικότητας του προγράμματος.

3.3 Εισαγωγή σχολίων σε κώδικα

Σε όλες τις γλώσσες προγραμματισμού είναι απαραίτητο να εξηγούμε ή να σχολιάζουμε κάποια κομμάτια του κώδικα. Αυτό σημαίνει πως θα πρέπει να γράψουμε φράσεις ή κείμενο σε φυσική γλώσσα, και ο compiler να το αγνοήσει πλήρως για να μην επηρεάσει καθόλου την διαδικασία της μετάφρασης.

Για εισαγωγή σχολίου σε μία γραμμή μόνο, γράφουμε μετά την εισαγωγή διπλής καθέτου //:

void add(int a, int b); // Δήλωση συνάρτησης. Αυτό το σχόλιο θα αγνοηθεί πλήρως από τον compiler

Για σχόλια που χρειάζονται πάνω από μία γραμμή, γράφουμε το κείμενο ανάμεσα στο άνοιγμα σχολίου με /* και στο κλείσιμό του με */:

/*
Εδώ δηλώνεται η συνάρτηση που δέχεται δύο ακεραίους ως παραμέτρους.
Το `int` στην αρχή σημαίνει απλά πως η συνάρτηση επιστρέφει επίσης ακέραιο.
*/
int add(int a, int b); /* Αυτός ο τρόπος σχολίων μπορεί να χρησιμοποιηθεί και σε μία γραμμή */

3.4 Εντολές Προεπεξεργαστή

Όταν πάμε να εκτελέσουμε μία εντολή μεταγλώττισης, όπως

g++ ...

πριν ξεκινήσει η διαδικασία μετάφρασης του κώδικα, ο προ-επεξεργαστής (preprocessor) καλείται πρώτος. Δεν εξετάζει καθόλου την ίδια στην σύνταξη της γλώσσας, αλλά μόνο ψάχνει τις γραμμές που ξεκινάνε με τον τελεστή #, όπως το #include, και τις αντικαθιστά με κώδικα, μεταβάλλοντας το κείμενο που ο compiler θα κληθεί να μεταφράσει.

Οι βασικές εντολές που μας ενδιαφέρουν για τώρα είναι οι #include, #define:

3.4.1 Η εντολή #include

Η εντολή αυτή συνοδεύεται με την διαδρομή (path) ενός header file (και όχι αρχεία πηγαίου κώδικα). Αν η διαδρομή είναι γραμμένη μέσα σε διπλά εισαγωγικά ως

#include "path/to/header.h"

ο προεπεξεργαστής ψάχνει το αρχείο header.h σε σχέση με το αρχείο στο οποίο είναι γραμμένη η εντολή. Αν για παράδειγμα βρίσκονται στον ίδιο φάκελο, τότε η σωστή εντολή είναι

#include "header.h"

ενώ αν βρίσκεται στον αμέσως πιο έξω φάκελο, η διαδρομή είναι

#include "../header.h"

Ο άλλος τρόπος να εισάγουμε την διαδρομή είναι μέσα σε <>, όπως

#include <header.h>

ή

#include <path/to/header.h>

Σε αυτή την περίπτωση, ο προεπεξεργαστής ψάχνει την διαδρομή του header.h όχι σε σχέση με το αρχείο στο οποίο είναι γραμμένη, αλλά σε σχέση με προεπιλεγμένους φακέλους ή φακέλους των οποίων την διαδρομή έχουμε επισημάνει στον compiler.

Η οδηγία #include είναι καθαρά αντικατάσταση κειμένου: ο προεπεξεργαστής (preprocessor) αντιγράφει ολόκληρο το περιεχόμενο του header file ακριβώς στο σημείο όπου βρίσκεται η οδηγία.

Η μεταφραστική μονάδα (translation unit) είναι το αποτέλεσμα αυτής της διαδικασίας. Είναι ένα αρχείο .cpp μαζί με όλα τα headers που περιλαμβάνει, άμεσα ή έμμεσα, αφού εκτελεστούν όλες οι οδηγίες του προεπεξεργαστή (#include, #define, #if, …). Αυτό ακριβώς είναι το κείμενο που βλέπει ο μεταγλωττιστής (compiler).

Κάθε μεταφραστική μονάδα μεταγλωττίζεται ανεξάρτητα από τις υπόλοιπες και παράγει ένα object file (.o). Στη συνέχεια, ο linker συνδέει όλα τα object files στο τελικό εκτελέσιμο. Επομένως, όταν ο compiler επεξεργάζεται μια μεταφραστική μονάδα, δεν γνωρίζει τίποτα για τις άλλες. Γι’ αυτό κάθε συνάρτηση ή στοιχείο που χρησιμοποιείται πρέπει να έχει δηλωθεί μέσα στην ίδια τη μονάδα, και αυτός είναι ο ρόλος των headers.

Συμβουλή

Μπορείτε να δείτε μια μεταφραστική μονάδα όπως τη βλέπει ο compiler, σταματώντας τη διαδικασία μετά τον προεπεξεργαστή:

g++ -E main.cpp -o main.ii

Ακόμα και ένα μικρό πρόγραμμα με #include <iostream> δίνει δεκάδες χιλιάδες γραμμές.

ΣημείωσηΆσκηση: Εξοικείωση με την εντολή #include

Στην άσκηση αυτή θα δούμε την δημιουργία συναρτήσεων με λίγα σύμβολα που δεν έχουμε δει ακόμα. Αγνοήστε τα, αρκεί απλά να ξέρετε πως απλά ορίσαμε μία συνάρτηση που τυπώνει κάτι στην κονσόλα μόλις εκτελεστεί.

Δημιουργήστε την παρακάτω δομή φακέλων:

greet_project/
├── main.cpp
└── include/
    ├── core/
    │   ├── greet.hpp
    │   └── shout.hpp
    └── walk.hpp

Μπορείτε να το κάνετε γρήγορα απλά εκτελώντας τις παρακάτω εντολές στο terminal:

  • Linux / macOS
  • Windows (PowerShell)
mkdir -p greet_project/include/core
cd greet_project
touch main.cpp include/walk.hpp include/core/greet.hpp include/core/shout.hpp
New-Item -ItemType Directory -Force greet_project/include/core | Out-Null
cd greet_project
New-Item -ItemType File main.cpp, include/walk.hpp, include/core/greet.hpp, include/core/shout.hpp

Στα αρχεία, βάλτε τα εξής περιεχόμενα.

include/greet.hpp
#include <stdio.h>

void greet() {
    printf("Hello from greet.hpp!\n");
}
include/shout.hpp
#include <stdio.h>

void shout() {
    printf("Shouting from shout.hpp!\n");
}
include/walk.hpp
#include <stdio.h>

void walk() {
    printf("Walking from walk.hpp!\n");
}
main.cpp
#include "include/core/greet.hpp"
#include "include/core/shout.hpp"
#include "include/walk.hpp"

int main() {
    greet();
    shout();
    walk();
    return 0;
}

Κάντε compile το main.cpp και εκτελέστε το εκτελέσιμο αρχείο:

g++ -o test_greet main.cpp  # compile
./test_greet                # run

Έπειτα, δείτε ποιά ακριβώς είναι η μεταφραστική μονάδα που βλέπει ο compiler:

g++ -E -o tu.ii main.cpp

Οι περισσότερες γραμμές στην αρχή είναι επικόλληση από το stdio.h>, ενώ στο τέλος είναι και ο δικός μας κώδικας.

Αν τώρα αποφασίσουμε να κάνουμε compile με την παρακάτω εντολή, η οποία λέει στον compiler να συμπεριλάβει και τον φάκελο include στους φακέλους που αναζητάει αρχεία, πώς θα μπορούσαμε να αντικαταστήσουμε τις 3 πρώτες γραμμές του main.cpp;

g++ -Iinclude -o test_greet main.cpp

Αν βρήκατε την σωστή απάντηση και γράφετε τον κώδικα στο VSCode, ο διακομιστής γλώσσας clangd που είδαμε στην αρχή, αν είναι ενεργοποιημένος, θα υπογραμμίζει με κόκκινο κάποιες γραμμές γιατί παραπονιέται πως δεν υπάρχουν τα αρχεία στις τροποποιημένες γραμμές με τα #include. Αυτό είναι φυσιολογικό καθώς δεν γνωρίζει για την εντολή -Iinclude που δώσαμε στον compiler. Αν θέλουμε ο clangd να γνωρίζει από πριν τις παραμέτρους που δίνουμε στον g++ ή στον clang++, θα πρέπει να τις δηλώσουμε στο αρχείο CMakeLists.txt όταν μάθουμε αργότερα πώς να φτιάχνουμε πιο οργανωμένα ένα project χρησιμοποιώντας το πρόγραμμα cmake.

3.4.2 Η εντολή #define

Με την εντολή #define <name> <value> ορίζουμε μακροεντολές (macros), ενημερώνοντας τον προεπεξεργαστή πως ό,που δει την μεταβλητή με το όνομα που δώσαμε, <name>, να αντικαταστήσει το κείμενό του με το κείμενο που έχουμε γράψει στο ακριβώς επόμενο πεδίο, <value>.

Για παράδειγμα, με την γραμμή

#define COUNT 10 //

ορίζουμε την μακροεντολή COUNT (είναι πολύ συνηθισμένη σύμβαση οι μακροεντολές να δηλώνονται με κεφαλαία) με τιμή 10. Είναι σημαντικό πως δεν έχει την τιμή 10 ως ακέραιο αριθμό, ο προεπεξεργαστής θα κάνει απλά αντικατάσταση κειμένου με το κείμενο “10”.

Δοκιμάστε να κάνετε compile το παρακάτω κείμενο.

#include <cstdio>

#define TEXT "Just some text"

int main() {
    printf(TEXT);
    return 0;
}

Μπορούμε να ορίσουμε macro’s που περιέχουν ολόκληρο κομμάτι κώδικα, χρησιμοποιώντας την ανάποδη κάθετο για να αλλάξουμε γραμμή και να συνεχιστεί η μακροεντολή:

#include <cstdio>

#define TEXT "Some text"

/*
Η C και η C++ δεν απαιτούν την αλλαγή γραμμής από εντολή σε εντολή.
Θα μπορούσαμε να γράψουμε ολόκληρο λειτουργικό σύστημα σε μόνο μία τεράστια γραμμή κώδικα.
Αλλά στην πράξη δεν το κάνουμε ποτέ αυτό γιατί δεν θα διαβάζεται ο κώδικας,
οπότε αλλάζουμε γραμμή πολύ συχνά για να κάνουμε τη ζωή μας πιο εύκολη.

Οι μακροεντολές δεν είναι κώδικας που βλέπει ο compiler και δεν εντάσσεται σε αυτόν
τον κανόνα, οπότε διαφορετικές μακροεντολές πρέπει να βρίσκονται σε διαφορετική γραμμή.
*/
#define CODE_BLOCK \  // Εδώ ξεκινάει η μακροεντολή
int main() { \
    printf(TEXT); // Εδώ τελειώνει ο ορισμός της

CODE_BLOCK // Ο preprocessor απλά κάνει επικόλληση εδώ
    return 0;
}

Δοκιμάστε να δείτε την μεταφραστική μονάδα (συγκεκριμένα τις τελευταίες γραμμές) που βλέπει ο compiler μετά την επεξεργασία του κώδικα από τον preprocessor, αφού αντιγράψετε τον παραπάνω κώδικα σε ένα αρχείο pre_test.cpp:

g++ -E -o tu_code.ii pre_test.cpp # Θα δημιουργηθεί το αρχείο tu_code.ii

Κοιτώντας τις τελευταίες γραμμές, θα δείτε πως δεν υπάρχει πουθενά η μακροεντολή TEXT ή CODE_BLOCK που ορίσαμε. Ο compiler δεν τις βλέπει ποτέ, και δεν θα γνωρίζει ποτέ για την ύπαρξή τους.
