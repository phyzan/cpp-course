2  Κατασκευή προγράμματος

2.1 Compilers - Interpreters

Οι δύο βασικές κατηγορίες γλωσσών προγραμματισμού είναι οι μεταγλωττιζόμενες (compiled) και οι διερμηνευόμενες (interpreted). Οι μεν μεταφράζονται εξ-ολοκλήρου μία φορά σε γλώσσα μηχανής από , ενώ οι δε, κάθε φορά που εκτελείται ένα πρόγραμμά τους, ένα άλλο πρόγραμμα (ο διερμηνέας)

Η μεγαλύτερη ειδοποιός διαφορά μεταξύ γλωσσών όπως οι C, C++, Rust, Fortran και γλωσσών όπως οι Python και MatLab είναι η διαδικασία εκτέλεσής τους. Οι μεν ανήκουν στην κατηγορία των μεταγλωττιζόμενων (compiled) γλωσσών (μεταφράζονται σε γλώσσσα μηχανής), ενώ οι δε ανήκουν σε αυτή των διερμηνευόμενων (interpreted). Για τις interpreted, κάθε φορά που εκτελείται ένα πρόγραμμά τους, μεταφράζονται στην αρχή σε μία εσωτερική λογική δομή από τον διερμηνέα τους (interpreter), και έπειτα ο διερμηνέας εκτελεί τις εντολές. Δηλαδή απαιτείται πάντα η ύπαρξη ενός δεύτερου προγράμματος για την εκτέλεση του πρώτου. Βρισκόμαστε δηλαδή μερικά επίπεδα πιο πάνω από αυτό του επεξεργαστή.

Ουσιαστικά, όταν τρέχουμε ένα πρόγραμμα Python, η εντολή στο terminal μοιάζει κάπως έτσι:

python3 my_script.py

Με αυτή την εντολή καλούμε το πρόγραμμα python3, ένα εκτελέσιμο αρχείο αποθηκευμένο κάπου στον δίσκο (.exe στα Windows). Το αρχείο αυτό περιέχει κώδικα σε γλώσσα μηχανής, προϊόν μεταγλώττισης προγράμματος γραμμένου σε C, και αναλαμβάνει να διερμηνεύσει το my_script.py.

Με άλλα λόγια, το my_script.py είναι για τον διερμηνέα ό,τι ακριβώς είναι ένα αρχείο .docx για το Microsoft Word: δεν εκτελείται απευθείας από τον επεξεργαστή, αλλά διαβάζεται και ερμηνεύεται από ένα άλλο πρόγραμμα.

Αντίθετα, για να εκτελέσουμε ένα πρόγραμμα γραμμένο στην C++, πρώτα θα πρέπει να καλέσουμε τον compiler για να το μεταφράσει σε γλώσσα μηχανής μία και καλή (ο οποίος compiler είναι και αυτός executable όπως η διερμηνέας της Python, αλλά κάνει εντελώς άλλη δουλειά),

g++ -std=c++20 -o executable main.cpp

και μετά το μεταφρασμένο πρόγραμμα executable μπορεί να εκτελεστεί οποτεδήποτε:

./executable # Linux

Ωστόσο, αν αλλάξουμε μία γραμμή σε ένα πρόγραμμα Python μετά αν ξανατρέξουμε το πρόγραμμα, η αλλαγή θα φανεί κατά την εκτέλεση, ενώ αν κάνουμε το ίδιο σε μία γραμμή κώδικα γραμμένου σε C++, η αλλαγή αυτή φυσικά δεν μπορεί να γίνει εμφανής κατά την εκτέλεση του προγράμματος αν δεν κάνουμε ξανά compile το πρόγραμμα.

Πράγματι, δοκιμάστε να κάνετε compile τον παρακάτω κώδικα αφού τον αποθηκεύσετε σε ένα αρχείο test.cpp

#include <cstdio>

int main(){
    printf("Hi there.");
    return 0;
}

με την εντολή

g++ -o test test.cpp

και αφού εκτελέσετε το πρόγραμμα που μόλις δημιουργήθηκε δίπλα στο test.cpp, αλλάξτε το μήνυμα στον κώδικα και ξανατρέξτε το.

Βέβαια, να ξεκαθαριστεί πως καμία γλώσσα από μόνη της δεν είναι απαραίτητα compiled ή interpreted. Υπάρχουν interpreters για την C++, καθώς και compilers για την Python, απλά δεν χρησιμοποιούνται συχνά.

2.2 Συναρμολόγηση προγράμματος

Συνήθως, όταν αναφερόμαστε σε ένα «πρόγραμμα», εννοούμε ένα εκτελέσιμο αρχείο, το οποίο περιέχει εντολές σε γλώσσα μηχανής, δηλαδή εντολές που μπορεί να εκτελέσει απευθείας ο επεξεργαστής. Ωστόσο, ένα αρχείο που έχει προκύψει από τη μεταγλώττιση (compilation) ενός προγράμματος δεν είναι απαραίτητα εκτελέσιμο από μόνο του. Μπορεί, για παράδειγμα, να περιέχει μόνο ορισμούς συναρτήσεων, οι οποίες προορίζονται να χρησιμοποιηθούν από κάποιο άλλο μέρος του προγράμματος.

Για παράδειγμα, μπορεί να έχω ένα αρχείο tools.cpp όπως το παρακάτω:

int add(int a, int b){
    // Μια συνάρτηση που παίρνει δύο αριθμούς ως παραμέτρους
    // και επιστρέφει το άθροισμά τους
    return a + b;
}

int sub(int a, int b){
    // Αντίστοιχα, επιστρέφει τη διαφορά τους
    return a - b;
}

Όταν μεταγλωττίσω αυτό το αρχείο, δεν υπάρχει απαραίτητα κάποιο σημείο εισόδου ώστε να ξεκινήσει να «συμβαίνει κάτι», και να μπορεί να εκτελεστεί αυτόνομα. Το αρχείο που προκύπτει, όμως, μπορεί να χρησιμοποιηθεί από το κυρίως αρχείο μου, main.cpp:

#include <cstdio>

// Δηλώνω ότι υπάρχουν αλλού οι ορισμοί των δύο συναρτήσεων,
// χωρίς να παρέχω εδώ τις πλήρεις υλοποιήσεις τους.
int add(int a, int b);
int sub(int a, int b);

// Η συνάρτηση με όνομα `main` είναι αυτή που
// ο compiler αναγνωρίζει ως κύρια, και αρχίζει να
// εκτελείται όταν ξεκινάμε το πρόγραμμα
int main(){

    int c = add(10, 20); // Αλλά πού βρίσκεται η συνάρτηση add;
    int d = sub(40, 45);

    printf("Addition: %d \n", c);     // Εκτυπώνει τον αριθμό c
    printf("Subtraction: %d \n", d); // Εκτυπώνει τον αριθμό d

    return 0;
}

Όταν, κατά την εκτέλεση του προγράμματος, έρθει η ώρα να υπολογιστεί η τιμή του ακεραίου c, το πρόγραμμα πρέπει να καλέσει τη συνάρτηση add. Πού βρίσκεται όμως ο κώδικας αυτής της συνάρτησης;

Ο compiler μεταφράζει τον πηγαίο κώδικα των tools.cpp και main.cpp σε κώδικα μηχανής, συνήθως μέσω της παραγωγής αντικειμενικών αρχείων (object files, .ο σε Linus και .obj σε Windows). Οι δηλώσεις των συναρτήσεων add και sub στο main.cpp ενημερώνουν τον compiler για τις υπογραφές τους, αλλά δεν παρέχουν τις υλοποιήσεις τους.

Το επόμενο βήμα είναι η σύνδεση (linking). Ο linker συνδυάζει τα αντικειμενικά αρχεία και επιλύει τις αναφορές προς συναρτήσεις που ορίζονται αλλού. Έτσι, μπορεί να αντιστοιχίσει την κλήση της add με την πραγματική υλοποίησή της στο tools.cpp και να δημιουργήσει το τελικό εκτελέσιμο αρχείο.

Όταν ξεκινήσει η εκτέλεση του προγράμματος, το λειτουργικό σύστημα φορτώνει στη μνήμη το εκτελέσιμο αρχείο και προετοιμάζει ό,τι απαιτείται για την εκτέλεσή του. Όταν έρθει η στιγμή να κληθεί η add, η εκτέλεση μεταφέρεται στη διεύθυνση μνήμης στην οποία βρίσκεται ο αντίστοιχος κώδικας. Ο επεξεργαστής δεν αναζητά τη συνάρτηση με το όνομά της, όπως κάνουμε εμείς όταν διαβάζουμε τον πηγαίο κώδικα. Η κλήση πραγματοποιείται μέσω των κατάλληλων εντολών μηχανής, αφού έχουν επιλυθεί οι απαραίτητες αναφορές.

Επομένως, η διαδικασία που επιτρέπει σε διαφορετικά τμήματα κώδικα να συνεργάζονται περιλαμβάνει δύο βασικά στάδια: τη μεταγλώττιση (compilation) και τη σύνδεση (linking).
